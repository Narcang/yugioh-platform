# Multi-game scanner preview

The `/scanner` lab selects Yu-Gi-Oh!, Pokémon, Magic: The Gathering, One Piece, Dragon Ball Fusion World or Riftbound. Switching games stops the old stream, terminates its worker, clears results and loads only the selected index. In-flight work from the old game cannot identify cards in the new game. This remains an isolated preview, separate from production table play.

Pokémon references are read from the existing public `pokemon_cards` table through the anonymous Data API. No schema, accounts, decks or room state are changed. The catalogue builder requires the project's existing `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`; no service-role key is used.

Each Pokémon card gets two reference crops: regular illustration and almost-full-card. Full-art variants work best with the complete upright card visible. Boundary-free illustration search uses a wider Pokémon artwork window. The worker preserves geometric confirmation thresholds and multi-frame confirmation.

Pokémon printings can share exactly the same illustration. The scanner groups competing references by card name for the confirmation margin and clearly labels the selected printing as a catalogue reference. Physical edition, language, foil finish and exact printing are not verified. This is an experimental artwork/name recognizer, not a collection valuation or printing authentication tool.

Generated Pokémon assets stay out of Git. Images are downloaded once from the two hosts already present in the catalogue (`images.pokemontcg.io`, `images.scrydex.com`), resized and re-hosted in small packs. Unavailable images are counted and excluded; a build fails if more than 1% (or five cards for a small catalogue) are missing. First build can take several minutes. Vercel source-image caches live under `.next/cache/scanner` for reuse on subsequent builds.

The full-card preview uses a same-origin route that looks up the public catalogue ID, restricts the upstream to these HTTPS hosts, validates the image content type, and caches the response. Camera frames continue to stay on the device.

Validation snapshot: 20,392 cards / 40,784 crop references available; 52 source images returned unavailable. Anonymous catalogue pagination returned all 20,444 records. The compact 8×8 shortlist index is approximately 9.5 MB uncompressed. Eleven representative cards (classic Pokémon, trainer, basic energy, VMAX, VSTAR, illustration rare, a recent Scrydex card and Unown question-mark ID) were tested clean, pixelated and rotated on a background: 33/33 card names recognized in one continuous worker sequence. Later variants exercise tracking. A shared-art energy resolved to another printing, confirming the need for the reference-printing notice. Yu-Gi-Oh regression: 60/60 identities; blank and wrong-game frames rejected. Game switching clears the old result, both preview providers and a punctuation ID load, a missing ID returns 404, and mobile layout has no horizontal overflow. These are synthetic/reference-image checks; real Pokémon webcam/language/foil tests are still required.

## Additional games

`src/lib/scanner-games.json` fixes each game's table, public columns, image hosts and crop profiles. `scripts/build-multigame-scanner-index.mjs <game>` reads these existing catalogues anonymously, downloads only allowed HTTPS image sources, writes regular-illustration and full-card references in eight-image packs, and emits an 8×8 shortlist index. Packs are flushed as they complete to bound build memory. Generated images and source caches are ignored by Git. `prepare-scanner.mjs` generates the four new indexes during preview builds. New-game indexes include their crop profile so worker and builder use exactly the same regions.

Existing catalogue sizes: Magic 35,306; One Piece 3,018; Dragon Ball Fusion World 2,005; Riftbound 1,020. Actual available counts and missing-image counts come from each generated index and are displayed in the UI. Missing source images are excluded; builds stop if more than 1% (or five for small datasets) are unavailable. No database, schema, RLS, accounts or deck contents are modified.

Source hosts are `cards.scryfall.io`, `static.dotgg.gg`, `www.dbs-cardgame.com` and `cdn.riftscribe.gg`. Scryfall requests carry the application's identifying User-Agent. The cached `/api/scanner/catalog-image/[game]/[cardId]` route looks up a fixed table by ID, restricts the host, disallows redirects and validates the content type and size. It does not accept arbitrary URLs. Preview proportions adapt to horizontal cards.

Magic confirmation groups by `oracle_id`, not printing ID. One Piece and Dragon Ball keep different playable card codes distinct even when their names match. Only One Piece DON cards and Dragon Ball energy markers are grouped by their shared gameplay identity; their decoration/printing is not verified. Riftbound keeps catalogue IDs distinct. A reference is always presented as a catalogue reference, not a claim to have read the physical card's code. The matching thresholds are preserved, with an additional inlier-spread check for the new games so a small shared text/symbol patch cannot confirm a match.

New-game extraction supports landscape quadrilaterals and a convex-hull rectangle fallback for rounded card borders. Frames/photos stay in the local worker. The game must be selected explicitly; no six-game index is downloaded at once. Only images actually present in the catalogue are indexed: alternate illustrations and reverse faces absent from the source are unsupported. In particular, Magic double-faced cards currently use the catalogue's front image. Language independence requires matching artwork, not text translation.

Run `node scripts/test-multigame-scanner.cjs` with a local scanner at port 3101 (or `BASE_URL`) and the generated `.scanner-cache` images. It checks clean, pixelated and rotated/background samples using a fresh worker for every sample, including leaders, events/spells, utility cards and horizontal Riftbound battlefields. Synthetic checks do not replace physical webcam/foil/translation testing.

Current reference coverage: Magic 35,092 available / 214 unavailable; One Piece 3,018 / 0; Dragon Ball Fusion World 1,998 / 7; Riftbound 1,020 / 0. Source images missing with HTTP 404 are excluded, not replaced by guessed card images.

The initial all-source Vercel build reached the 45-minute build limit while processing Riftbound. Preview builds now first restore the unchanged Yu-Gi-Oh! and Pokémon packs from our immutable, already-tested Pokémon preview. `restore-scanner-baseline.mjs` pins both index SHA-256 checksums, validates referenced shard IDs and pack membership, and writes the index only after all packs succeed. A missing/deleted/incompatible baseline falls back to the existing source builders. Only public reference assets are fetched; camera photos, credentials and application source are never copied. This avoids re-encoding the two existing catalogues for the four-game extension.
